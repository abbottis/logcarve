## Open owner decisions (one asked at a time, in this order)

1. License and any LogWerk reuse — ACCEPTED 2026-10-29 by owner: Apache-2.0 for original LogCarve code and documentation; third-party components keep their respective licenses; no LogWerk code or assets are imported until source, license, copyright and required notices are verified and documented. License choice only; GOV-02 still needs its other prerequisites.
2. Deployment host and external-access/TLS policy — ACCEPTED 2026-10-29 by owner: private Linux x86-64 host or VM with Docker Compose is the MVP deployment and installation-verification target; macOS stays the development environment; default to loopback exposure; remote access only via TLS reverse proxy with application authentication retained; Plesk integration deferred and untouched. Record the actual test environment; mark unavailable Linux verification BLOCKED and continue independent work. No infrastructure purchases, public exposure or production deployment authorized.
3. Meta account, credits and T8 smoke-call caps — ACCEPTED 2026-10-29 by owner: verify-then-capped-smoke. Real-provider execution stays BLOCKED until the owner verifies team account, credited balance, model access and effective Standard handling outside the transcript and explicitly authorizes the prepared run. Maximum allowance: three synthetic investigations, twelve provider requests including retries, USD 1.00 estimated product cost, tighter existing limits binding. No provider calls or spending authorized by this decision. Independent implementation and fake-provider testing continue; AI-01/02 stay NOT RUN until authorized execution provides evidence.
4. Local checkout versus remote integration path — ACCEPTED 2026-10-29 by owner: separate clone followed by reconciliation on a feature branch. Use existing remote history as the branch base; recheck remote HEAD (currently reported main revision 836769b); compare remote contents with this scaffold before transferring files; preserve local planning work and remote history, resolving conflicting requirements explicitly without wholesale overwrite; check provenance and licenses before adopting existing code or assets; exclude credentials, real logs and generated artifacts; verify the reconciled checkout contains the applicable AGENTS.md instructions before continuing implementation there. No push, force-push or modification of remote main.
5. Retention period and backup/restore expectations — ACCEPTED 2026-10-29 by owner: configurable 30-day default retention for imported events, based on event timestamps in UTC. Delete only LogCarve-owned imported events and related derived data; never modify or delete source logs. Backups use SQLite's supported online backup API for consistency (never a live main-file copy in WAL mode), stored with restrictive permissions outside version control; rotation and expiry documented separately, and deleting live records does not remove them from existing backups. Restoration is tested in an isolated environment covering integrity, expected analytics and retention behavior, and current retention is reapplied before restored data is served.
6. Findings derived on read versus persisted — ACCEPTED 2026-10-29 by owner: deterministic findings derived on read for the MVP through the shared analytics layer (dashboard, external REST API and internal assistant tools alike), working without an LLM. Each finding includes rule ID and version, evidence filters and requested time window, actual data coverage and observation time, supporting counts and relevant limitations. Results are reproducible for the same normalized dataset, rule version, filters and time window, with stable sorting; heuristic matches are described as investigation candidates. Persisted finding lifecycle states and review workflows are deferred to P1.
